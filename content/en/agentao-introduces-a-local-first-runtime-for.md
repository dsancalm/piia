Researchers introduced Agentao, a local-first runtime designed for LLM agents that use tools and modify local states. The system uses a layered architecture to separate action proposals generated by the model from the execution authorized by the host. This separation prevents the agent from executing arbitrary commands without passing through a host-controlled verification layer.

The architecture includes host-oriented surfaces, a host contract, a runtime core, a permission-mediated tool system, and subsystems for memory, replay, plugins, skills, sub-agents, and protocol integration. This structure allows developers to build agents that are easier to govern and inspect. The mediation layer abstracts permissions, state, protocol boundaries, and execution traces. This approach solves the problem of managing agents that have direct access to local files or system commands.

## Governance through abstraction

Developers can intercept and validate an agent's intended actions before they occur. Instead of giving an LLM direct access to a shell or a database, users interact with the Agentao runtime. The runtime mediates and enforces the host contract. If an agent proposes an action that violates predefined permissions or state constraints, the runtime blocks the execution or requires manual intervention.

This architecture provides a structured way to implement human-in-the-loop patterns or automated policy enforcement. The system includes a replay subsystem to record agent interactions. Users can re-run these interactions to debug where an agent's reasoning diverged from the intended tool usage.
