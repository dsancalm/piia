A single Swift binary called `slotstream` now runs Qwen3.8-Flash-Next, a 125-billion-parameter mixture-of-experts model quantized to 4-bit (104 GB on disk), on Apple Silicon Macs with as little as 16 GB of RAM. On a 48 GB M5 Pro it decodes at roughly 12 tokens per second with a peak memory footprint of 32 GB. The engine starts in about two seconds because it only loads the 3.8 GB dense trunk; the remaining 68 GB of routed experts and a 32 GB n-gram table stream from the SSD on demand.

```bash
curl -fsSL https://raw.githubusercontent.com/carloslfu/slotstream/main/install.sh | sh
```

The installer places the binary in `~/.slotstream/bin`, adds it to your PATH, and creates a wrapper at `/usr/local/bin/slotstream`. Uninstallation is a manual `rm -rf ~/.slotstream` plus removal of the wrapper or the PATH line. You can verify the release artifact with `gh attestation verify slotstream-arm64.tar.gz --repo carloslfu/slotstream` or build from source using only the Command Line Tools.

### How the streaming works

The model architecture splits into a small resident trunk and 512 experts per layer (10 active per token). Traditional memory-mapping fails here because MLX cannot materialize a slice of a mapped tensor; a top-10 gather would fault in the entire 100 GB expert layer. `slotstream` avoids this by managing its own fixed-slot cache shared across all 48 layers. Hot layers borrow slots from cold ones. The cache size is chosen automatically as the minimum of 33 GB, 70 percent of physical RAM, and the Metal working-set limit minus 2 GB. The daemon re-evaluates every 15 seconds and resizes the cache between requests with byte-identical output.

The first model pull downloads 103.8 GB across 24 files using eight parallel TCP connections. At 1 Gbit/s it took 16 minutes (112 MB/s); at 100 Mbps expect roughly two hours twenty minutes. Resumption and SHA-256 verification are built in.

### Serving and context

`slotstream serve` exposes Ollama- and OpenAI-compatible chat endpoints on port 11434. Maximum context is 32,768 tokens. Initial prefill is slow (about one minute for 8k tokens on 48 GB, over three minutes on 16 GB) but subsequent turns reuse the prefix cache, keeping time-to-first-token flat. The eighth turn in a 16 GB test took 6 seconds versus 25.8 seconds without cache reuse. Disable this with `--no-prefix-cache` for strict reproducibility.

Optional Multi-Token Prediction adds a 1.6 GB draft head that guesses the next token and verifies it in a two-token pass. The draft hits 86 percent accuracy. Auto-enable kicks in when the memory target reaches roughly 28 GB, where the extra head fits without evicting experts. On 48 GB this lifts throughput from 10.1 to 11.8 tok/s (×1.17). Theoretical ceiling with all experts resident is ×1.4. Enabling MTP requires a one-time conversion that downloads 4.9 GB and writes a 1.5 GB `mtp.safetensors` file.

### Performance table

The project publishes a RAM-vs-throughput table generated by `slotstream doctor --sim-ram N`. Only the 48 GB row is a real measurement; the rest are curve estimates.

A 512 GB disk is the practical minimum; the model alone consumes 110 GB and the SSD fills first.

### Limitations in v0

Only one model (`qwen3.8-flash-next:4bit`) is supported. No tools, images, JSON schema, or logprobs (these return explicit 400 errors). The installer has been tested on macOS 14 and 15; the engine itself has not been explicitly validated on 15. Full API documentation lives in `docs/API.md`.

### What is not known

- Actual performance on 8/16/24/32 GB machines (only curve estimates exist).
- Behavior under extreme memory pressure with other applications open.
- Long-term availability and stability of the weight mirror and Hugging Face fallback.
- Knowledge cutoff date for Qwen3.8-Flash-Next.
- License terms for the model weights.
- Bit-for-bit reproducibility with MTP enabled (the draft head introduces variability).
- Support timeline for additional models or quantization formats.
