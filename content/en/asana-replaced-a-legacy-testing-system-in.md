Asana utilizó OpenAI Codex para reemplazar un sistema de pruebas heredado en solo dos semanas. Originalmente, la migración se proyectó para requerir cinco años de esfuerzo de ingeniería. La empresa logró esta reducción al usar el modelo para automatizar la lógica repetitiva necesaria para pasar de su antiguo marco de trabajo a uno nuevo.

Este cambio altera la forma de estimar la deuda técnica y los proyectos de migración. La mayoría de los gerentes de ingeniería planifican las migraciones basándose en horas de trabajo humano y refactorización manual. Este caso demuestra que las transformaciones de código a gran escala ya no son esfuerzos puramente manuales. Si debe migrar una base de código masiva a un nuevo lenguaje o marco de trabajo, el punto de referencia para su cronograma ha cambiado. Debe considerar que los modelos de lenguaje extenso (LLM) pueden manejar la mayor parte de la traducción estructural, lo que reduce el alcance del trabajo de años a semanas.

## El impacto en la estrategia de migración

El caso de Asana demuestra que el principal cuello de botella en las migraciones suele ser el volumen de código repetitivo y de estructura básica (boilerplate). Los sistemas heredados suelen incluir miles de pruebas y estructuras de datos que deben reescribirse para adaptarse a una nueva arquitectura. Codex permitió al equipo automatizar esta traducción.

En lugar de escribir envoltorios manuales o scripts de conversión para cada módulo, los ingenieros usaron el modelo para generar los patrones de código necesarios. Esto permite que un equipo pequeño aborde proyectos que de otro modo requerirían un grupo de trabajo dedicado durante cinco años. El refactorizado a gran escala ahora puede tratarse como una tarea automatizada de alta velocidad en lugar de un proceso lento de varios años.

No se sabe cuál fue el flujo de trabajo exacto que los ingenieros usaron para verificar el código generado ni los prompts específicos para lograr este nivel de automatización.
